\# AI Usage Report



\## 1. AI Tool Used



ChatGPT was used as an AI assistance tool during the development of the Student Support \& Ticket Management System.



\## 2. What I Asked AI to Do



I used AI assistance for:



\- Understanding the assignment requirements

\- Planning the application structure

\- Designing the student support ticket workflow

\- Creating Django REST Framework backend code

\- Creating React frontend components

\- Designing database models

\- Implementing JWT authentication

\- Creating REST APIs

\- Debugging development errors

\- Setting up PostgreSQL

\- Git and GitHub guidance

\- Preparing project documentation



\## 3. Most Useful Prompts



Some of the useful prompts used during development were:



\- "Help me build a Student Support \& Ticket Management system using React, Django REST Framework and PostgreSQL."

\- "Create Django models for tickets, categories, comments and activity history."

\- "Create REST APIs for ticket creation, assignment, status updates, comments and escalation."

\- "Create React pages for student, staff and manager dashboards."

\- "Help me debug the login and category dropdown issues."

\- "Explain how to push the project to GitHub."



\## 4. Code Generated by AI



AI assistance was used to generate initial versions of:



\- Django models

\- Serializers

\- API views

\- Permissions

\- URL configurations

\- React components

\- API service configuration

\- Dashboard components

\- Authentication flow

\- Ticket workflow logic



The generated code was integrated into the project and tested locally.



\## 5. Code Modified by Me



I modified and configured the generated code based on the actual project requirements and testing.



Changes included:



\- PostgreSQL database configuration

\- Environment variable configuration

\- User roles

\- Ticket categories

\- Ticket priorities

\- SLA durations

\- Ticket status workflow

\- Frontend API configuration

\- Login configuration

\- UI and dashboard behavior

\- GitHub project setup



\## 6. AI Output That Was Wrong or Needed Correction



During development, some issues were identified while testing the application.



Examples included:



\- Login credentials did not initially work as expected.

\- The category dropdown did not initially display categories.

\- Some setup commands caused errors because application folders already existed.

\- GitHub push initially failed with an HTTP 408 error.



\## 7. How I Identified the Issues



I identified these issues by:



\- Running the application locally

\- Testing login with the created accounts

\- Checking the Django database using Django shell

\- Checking API responses

\- Checking frontend behavior

\- Running Git commands and reviewing their output

\- Testing the complete student and staff workflow



\## 8. How I Fixed the Issues



The issues were fixed by:



\- Resetting and verifying user passwords

\- Creating and verifying ticket categories in the database

\- Avoiding duplicate Django app creation

\- Correcting project configuration

\- Reviewing Git repository configuration

\- Retrying the GitHub push after checking the repository state



\## 9. Validation



The final application was tested using an end-to-end workflow:



Student:



1\. Login

2\. Create a support ticket

3\. Select category

4\. Select priority

5\. Submit ticket

6\. View the ticket



Staff:



1\. Login

2\. View student ticket

3\. Assign ticket

4\. Update ticket status

5\. Add comments

6\. Resolve the ticket



Manager:



1\. Login

2\. View dashboard

3\. View ticket statistics

4\. Monitor ticket status and workload



\## 10. Final Validation



The application was tested locally and the main student, staff and manager workflows were verified before preparing the project for submission.



\## 11. Reflection



AI was used as a development assistant rather than as a replacement for testing or decision-making. Generated code was reviewed, integrated, tested and modified based on the application's actual behavior.
